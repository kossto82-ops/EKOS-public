# Architecture Decision Record (ADR) Log

A running log of the significant technical decisions taken on EKOS, each with the
reasoning behind it. This is the "why is it built this way" companion to the code —
skim it before proposing a structural change.

For the boundary between what the prototype does today and what a production build
would own, see [KNOWN_LIMITATIONS.md](./KNOWN_LIMITATIONS.md).

| ADR | Date | Decision | Rationale |
| :--- | :--- | :--- | :--- |
| **001** | 2026-06-26 | Server-side proxy for all external integrations | Keeps database credentials and provider API keys out of the client bundle. |
| **002** | 2026-06-26 | `localStorage` as a fallback for session state | Client resiliency and fluid UX during transient network disruptions. |
| **003** | 2026-06-26 | Component-scoped design tokens | Consistent enterprise aesthetic without ad-hoc styling drift. |
| **004** | 2026-06-26 | Decoupled integration connectors | Lets ingestion, sync and indexing agents deploy independently. |
| **005** | 2026-06-28 | Decompose monolithic view files | Split large views (AssistantTab, GovernancePanel) into isolated components to improve build times, hook memoization, and readability. |
| **006** | 2026-06-29 | Strip API keys from client-side storage | Excludes raw `apiKey` from client `localStorage`; server orchestrates provider keys. |
| **007** | 2026-06-30 | Brand-aligned user roster | Re-aligned `INITIAL_USERS` into language/country brand groups for realistic RBAC simulation. |
| **008** | 2026-06-30 | Remove redundant `splitVendorChunkPlugin` | Conflicted with manual `manualChunks` in `vite.config.ts`, producing empty vendor bundles. |
| **009** | 2026-06-30 | Global user-simulation switcher | Header control to demo localized RBAC states live and avoid test-profile lockouts. |
| **010** | 2026-06-30 | Encrypt persisted provider keys | AES-256-CBC over stored keys, keyed from `ENCRYPTION_SECRET`, to blunt a DB-leak exploit. |
| **011** | 2026-07-03 | Server-side RBAC middleware (interim, pre-IdP) | `src/server/middleware/auth.ts` re-checks `rbac.ts` on every `/api/db/*` and AI route. Narrows — does not close — the "any caller, no check" gap; identity is still an unsigned id, not a verified JWT. |
| **012** | 2026-07-03 | Accessibility regression gate in CI | First CI pipeline (`.github/workflows/ci.yml`) plus `axe-core` tests over shared Modal/Breadcrumb/Toast primitives. Caught a real `role="dialog"` misuse on first run. |
| **013** | 2026-07-03 | Virtualized KB document list | `react-window` in `DocList.tsx` flattens categories into one header+doc row sequence so render cost stays flat regardless of document count. |
| **014** | 2026-07-03 | Client-side telemetry seam | `src/utils/telemetry.ts`'s `reportError()` is the single client error-capture call site (ErrorBoundary + global handlers). Sinks to `console.error` today; the seam a real APM plugs into. |
| **015** | 2026-07-03 | Search trustworthiness fixes | Rescored `fuzzyMatch` to weight distinct-keyword-match count over raw weight; added `retrievalSource` so the UI labels an answer as simulated when the AI backend failed and the local fallback served. |
| **016** | 2026-07-03 | Full-screen accessibility CI coverage | `tests/fullScreenAccessibility.test.tsx` runs `axe-core` over every tab screen under the real provider tree (six at the time, seven since ADR 031); first run found two always-present violations, both fixed. |
| **017** | 2026-07-04 | Server-side document pagination | `limit`/`offset` (default 200, cap 1000) on `GET /api/db/documents` with `hasMore`/`nextOffset`; `DocList` shows "Load more" when more pages exist. |
| **018** | 2026-07-15 | Code-split heavy document parsers | `pdfjs-dist`, `mammoth` and `xlsx` moved to dynamic `import()` in `src/utils/extractFileText.ts` and named as `vendor-pdf`/`vendor-docx`/`vendor-xlsx` chunks. They load only when a user uploads a matching file, cutting the `KnowledgeBaseTab` chunk from 1.47 MB to 168 KB. |
| **019** | 2026-08-05 | One failure envelope, produced centrally | `src/server/middleware/errors.ts` owns every failure response. Two shapes used to coexist and the client only parsed one, so `/api/db/*` error reasons were silently dropped; `e.message` also relayed internal SQLite/provider text to callers. |
| **020** | 2026-08-05 | Zod validation at the API boundary, reusing the UI's schemas | `src/server/schemas/apiSchemas.ts` + `validate` middleware. `AiProviderConfigSchema`/`DeskSettingsSchema` are shared with the forms so a direct API call can't store state the UI would refuse — `POST /governance/ai-config` previously accepted any JSON as the live provider config. Tolerances that *corrected* input (page clamping, `type` fallback) are preserved as transforms, not turned into new 400s. |
| **021** | 2026-08-05 | pino as the single server log sink | `src/server/logger.ts`. One JSON object per event with a level and the client's `requestId`, replacing ~41 prefixed `console.*` calls that could be neither filtered nor correlated. Silent under test; stdout today — swapping in an OTel/APM transport is a change to this file only. |
| **022** | 2026-08-05 | Unauthenticated `/healthz` + `/readyz`, with what they may say constrained | Probes have no identity to present, so these routes report *whether* each dependency works and never how much data is in it (counts stay behind `GET /api/embeddings/status`). Liveness deliberately touches no dependency: restarting a container because the database is down fixes nothing. |
| **023** | 2026-08-05 | WAL + `busy_timeout`, `synchronous` left at FULL | Readers no longer block on a concurrent sync write, and lock contention becomes latency instead of a `SQLITE_BUSY` 500. FULL is kept against the usual WAL/NORMAL pairing because this file holds governance decisions and NORMAL can lose the last commits on an OS crash. |
| **024** | 2026-08-05 | Drain connections before closing the database | `src/server/shutdown.ts` — extracted from `server.ts` precisely because the order is the whole point and untestable end-to-end on Windows (no real SIGTERM delivery). Closing the database first would fail the in-flight requests the drain exists to protect. |
| **025** | 2026-08-05 | Versioned migrations, with a hand-edited baseline | `drizzle-kit generate` + `migrate()` at startup replace ~200 lines of boot-time `CREATE TABLE IF NOT EXISTS` and a hand-maintained ALTER list that could only add columns and recorded nothing. `0000_baseline.sql` uses IF NOT EXISTS so a database created by the old DDL adopts migrations instead of failing startup; a test forbids that pattern in every later file. |
| **026** | 2026-08-05 | One route registry as the API's source of truth | `src/server/apiRegistry.ts` lists every route with its guard and its request/response schemas. OpenAPI is generated from it (Zod 4's native `toJSONSchema`, no new dependency), and a test walks the Express stacks so an unregistered route fails CI. Prose could never be checked against a router; this can. |
| **027** | 2026-08-05 | Response schemas are deliberately loose | They assert the fields clients would crash without and let extra DB columns through. Pinning every nullable column would break the suite on each new column; asserting nothing would make the contract decoration. |
| **028** | 2026-08-05 | Generated artifacts are compared normalized, and the working tree is pinned to LF | `.gitattributes` sets `* text=auto eol=lf`, and `tests/apiSurface.test.ts` normalizes line endings before comparing `docs/openapi.json`. The byte-exact compare failed on every Windows clone (`core.autocrlf=true` checks LF blobs out as CRLF) and passed on the Linux runner — a stale-spec alarm firing on the checkout config. An alarm that cries wolf about the environment trains readers to ignore it. |
| **029** | 2026-08-05 | Claims of *absence* are guarded like counts | `tests/docsDrift.test.ts` fails any doc that denies a retrieval capability the code has; that test holds the canonical list of forbidden phrasings, deliberately not repeated here — a doc quoting them would trip the guard, and one source of truth beats two. README's credibility box denied the vector half for the whole life of the shipped RAG pipeline while every other doc was corrected, *underselling* the system. The guard is keyed to `src/server/{vectorStore,embeddings,hybridRetrieval}.ts` existing, so removing that half makes the denials true and silences the guard on its own. |
| **030** | 2026-08-05 | Eval artifacts carry the config that produced them | `scripts/eval-retrieval.ts` stamps `vectorRelativeFloor`/`minVectorScore`/`rrfK`/`topK` into `eval/baseline.json`, and a test pins that stamp to the shipped constants. The committed baseline had silently become the numbers of a retired configuration (floor 0.9, 16 misses) after the sweep moved the constant to 0.95 (10 misses): metrics without provenance cannot be checked against anything. The README's quoted hit@1/hit@5/MRR are now derived from that file by the same test. |

| **031** | 2026-08-07 | Review queue promoted to a top-level destination | `KnowledgeBaseTab` served three jobs behind an internal switch — browse the repository, read analytics, approve content — so a librarian and a compliance reviewer landed on the same screen. `review` is now its own route reusing the `governance` predicate verbatim (`rbac.ts` comments the two cases as one, so they cannot drift), and the sidebar labels were corrected: the knowledge base was called "Queue" while the queue sat two clicks inside it. Rejected: folding the queue into the existing Governance tab, which holds AI config, brands, teams and policies — that mixes a daily workflow into screens consulted monthly and would have worsened the admin tab to fix the KB one. |
| **032** | 2026-08-07 | Cross-tab handoffs use a drained slot, not an event | Resolving a search gap from Metrics opens a sandbox that now lives on another tab. The first version dispatched a `CustomEvent` with the payload and then navigated; only one tab is mounted at a time, so the receiver added its listener *after* the send and the action silently did nothing. `src/utils/crossTabIntent.ts` is a slot the sender fills and the receiver drains on mount, which has no ordering requirement; `take` clears as it reads so a stale intent cannot re-fire. `navigate_tab` stays an event — it carries only a destination and App is always mounted. |
| **033** | 2026-08-06 | Design-system debt is guarded, not just paid down | A review scored design 60/100 because the primitives existed with almost no adoption, so one concept had several implementations. Five were consolidated (badges, empty states, tables, overlay scrims, micro type) and `tests/designSystem.test.ts` distinguishes **closed** conventions — a second implementation anywhere fails — from **ratcheted** ones, which pin a count so debt cannot grow while it waits its turn. A ratchet is an admission, not a pass. Consolidating once does not fix compounding; the next feature rebuilds the same thing unless something fails when it does. |
| **034** | 2026-08-06 | Dialogs are audited open, in two layers | The prior suites scanned `Modal` as an isolated primitive and tab screens in their settled default state, so every dialog was covered only while closed — which is how a hand-rolled `role="dialog"` with no focus trap passed CI. `tests/dialogAccessibility.test.tsx` pairs a static guard over `src/` (anything declaring dialog semantics must call `useFocusTrap` *and* attach the ref) with an interaction layer that opens all fourteen surfaces and drives real Tab/Shift+Tab. Neither layer suffices alone: interaction tests are never written for a dialog nobody knows bypassed the shell, and a text search cannot see whether the hook is wired. |
| **035** | 2026-08-07 | Backup liveness is reported by the app, not scraped from the backup | The backup container writes a heartbeat file after a cycle it has verified with `quick_check`; the `ekos` service mounts that volume read-only and reports its age as `ekos.backup.last_success.timestamp`. Chosen because the backup runs in the default compose profile while Prometheus only runs under `observability` — a scrape target inside the optional profile would monitor backups only when someone opted into monitoring. `EkosBackupStale` alerts on age *or* on the metric being absent, one rule for "failing" and "stopped happening"; the second is the failure a counter cannot see. |
| **036** | 2026-08-07 | One crawled file, one document — matched on content, exactly | The SharePoint index returns some files twice, once under the real name and once under the Windows 8.3 short name (`TOTP_C~1.MD` beside `TOTP_Configuration_Audelia.md`, identical but for a trailing newline). Two item ids meant two rows, so search ranked both and deleting one left the other answering identically — from the user's side, indistinguishable from a delete that did not stick. `upsertKbDocuments` now ingests one row per content fingerprint, choosing the winner from the **name** so the outcome does not depend on crawl order, and leaving the loser out of `seenIds` so ADR-era tombstoning cleans a twin already in the KB. The match is exact (whitespace-collapsed, case-insensitive) and never fuzzy: the library holds two overlapping *Employee Directory Transformer* write-ups by different authors that are **not** duplicates, and a similarity threshold loose enough to catch near-misses would have destroyed one of them. |
| **037** | 2026-08-07 | The answer's structure is dictated, not left to the model | The `/api/search` prompt asked for `content (markdown)` and nothing more, so formatting tracked the answer language: the same SOP came back as headed, numbered steps in French and as prose in the other seven locales. Neither the corpus (uniformly `##` sections and numbered procedures) nor the renderer (one shared react-markdown/GFM component) varied — only the instruction, which did not exist. `ANSWER_CONTENT_FORMAT_CONTRACT` states the shape once, generically, and is byte-identical in every locale, sitting **before** the language instruction so translation applies inside the structure rather than replacing it. Structure is a property of the source document, not of the language it is answered in. What the test can pin is the contract reaching the model on every request, not the model obeying it — the second is the provider's behaviour and belongs to evaluation, not CI. |
| **038** | 2026-08-07 | A gate that has never run is not a gate | The image job was pinned to `aquasecurity/trivy-action@0.28.0`, a tag that stopped resolving when the action moved to immutable `vX.Y.Z` releases. Resolution fails before checkout, so the run went red in 3s with no failing step, on every commit for days, while the quality gate beneath it passed every test. Worse, the compose integration test and that broken pin landed in the **same commit** (ffd5623): the test written to exercise the stack had therefore never executed once, and found a crash-looping backup sidecar on its first real run. `tests/deployment.test.ts` now requires every `uses:` to pin a v-prefixed tag or a full sha — a test cannot ask GitHub which tags exist, but it can forbid the shape that stopped resolving. |
| **039** | 2026-08-07 | The runtime image carries only what it runs | The first completed Trivy scan found 11 fixable Debian CVEs (2 CRITICAL) plus 30 more in two esbuild binaries, and several in npm's own bundled tree — almost none of it code this service executes. Three changes, one principle: Debian security upgrades are applied at build time (the `node:X-bookworm-slim` images are rebuilt on the publisher's cadence, not the archive's, so pinning a newer NODE_VERSION closes it today and reopens it in weeks); Vite and its plugins moved to devDependencies, which required making server.ts's Vite import dynamic because `--packages=external` turns a top-level import into a runtime `require()` resolved even in production; and npm, npx, corepack and yarn are deleted from the runtime stage, since a container that cannot install packages also cannot be made to install one. Accepted cost: two builds of one commit can differ in OS package versions. |
| **040** | 2026-08-07 | One dependency comes from the vendor, not from npm | `npm install xlsx` returns 0.18.5 and always will — SheetJS stopped publishing there — leaving prototype pollution (CVE-2023-30533) and ReDoS (CVE-2024-22363) permanently unpatched in the library this app hands user-uploaded spreadsheets. `npm audit` says "No fix available" and is right about npm; the fixed releases exist only on SheetJS's own distribution, which is where this one is pinned. Rejected: a `.trivyignore`, because the exposure is exactly the described input, and swapping the library, which is the better long-term answer but a code change rather than a source change. The cost — `npm ci` must reach cdn.sheetjs.com — is in the README's prerequisites, and a test pins both package.json and the lockfile's resolved URL, because the regression is one innocent `npm install xlsx`. |

| **041** | 2026-08-13 | Dual-mode authentication behind config, not a rewrite | `src/server/auth/config.ts` selects `legacy` (unsigned Bearer id, the interim scheme — default so dev/demo/tests are unchanged) or `oauth` (real corporate session), chosen by whether `AUTH_CLIENT_ID`/`AUTH_CLIENT_SECRET` are set. `requireUser` branches on it; `requireTab`/`requireAction` and `rbac.ts` are untouched — only the *source of identity* changes. Rejected a hard cutover, which would have broken the impersonation demo and every test that authenticates with a user id. |
| **042** | 2026-08-13 | Backend-for-frontend login, tokens never reach the browser | `src/server/routes/auth.ts` runs the OAuth2 authorization-code + PKCE flow server-side; the corporate access/refresh tokens live in `auth_sessions` **encrypted at rest** (`crypto.ts`, reusing the provider-key AEAD), and the browser holds only a signed `httpOnly`+`SameSite` cookie. The corporate server issues **opaque** tokens, so validation is by introspection (`/oauth/check_token`), cached short-TTL and fail-closed — not local JWT signature checks. Closes XSS token-exfiltration and CSRF without a token-in-JS dance. See [AUTH_INTEGRATION_PLAN.md](./AUTH_INTEGRATION_PLAN.md). |
| **043** | 2026-08-13 | Corporate→EKOS identity mapping is a DB table, not AD claims | `user_directory` (migration `0001`) maps a corporate `user_name` to an EKOS role/department/brand/permissions, seeded from `INITIAL_USERS` (username = email local-part) and resolved by `src/server/auth/identityMap.ts`. Chosen over deriving roles from the token's AD `authorities` array, which would couple EKOS permissions to AD group naming we don't control. An authenticated user with no active row fails closed (**403**) — authenticated ≠ authorized. |
| **044** | 2026-08-13 | Endpoint exposure is declared and gated, not inferred | `src/server/exposure.ts` classifies every route `internal` (infra-only probes) or `external` (browser-reachable), enforcing SecurityGuidelines §12: exposure can't be read off the code (at dev time every route is reachable), so `tests/exposureClassification.test.ts` fails if a route is unclassified or an invariant breaks, and `openapi.ts` stamps `x-exposure`. No corporate `external_lb_whitelist.yaml` is fabricated — EKOS is standalone, not behind that shared LB; see [ENDPOINT_EXPOSURE.md](./ENDPOINT_EXPOSURE.md). |

## Format

New entries append to the bottom, numbered sequentially. Keep each row to a one-line
decision plus a one-line rationale; if a decision needs more than that, link to the
doc or code that carries the detail rather than expanding the table.
